## Продолжить в том же Sites-проекте

Если в новом окружении доступны Sites и аккаунт владельца, используй существующий `project_id` из `.openai/hosting.json`. Прочитай актуальные инструкции Sites и текущее состояние проекта, открой его канонический исходный репозиторий через поддерживаемый workflow и перенеси туда изменения из этого пакета.

Не создавай второй Site вместо существующего, не придумывай Git remote или токены. Для текущего публичного сайта публикация идёт через обычный публичный workflow сохранения версии и deployment; private-only endpoint не подходит. Сохраняй публичную аудиторию.

Наличие manifest не означает, что `npm run dev` публикует код: эта команда только запускает локальную игру.

## Использовать другой статический хостинг

Публикуй **содержимое `dist/`** как корень сайта. Команда сборки отсутствует. Node-сервер из `scripts/` нужен для локальной разработки, не обязателен на production.

Требования: HTTPS для нативного sharing/clipboard; корректная раздача `.js` как JavaScript; относительные импорты и ассеты доступны. Environment variables, API keys и серверная база для текущей игры не нужны.

Не публикуй весь репозиторий как каталог файлов: для сайта достаточно `dist/`. Корневые документы, тесты и `.openai` в сайт не входят.

При новом домене прогресс старого сайта автоматически не появляется. До переезда игроков стоит добавить экспорт/импорт сохранений или сохранить старый origin. Стандартное браузерное localStorage нельзя прочитать с другого origin.

## Репозиторий GitHub

Репозиторий для разработки: https://github.com/vitpanov/eat_athlete_game_v1, основная ветка `main`. Владелец создал его и предоставил для переноса проекта. Он содержит подготовленный код beta и инструкции для Codex Cloud. История оригинального Sites Git не включена; исходный commit записан для сопоставления, но не является коммитом нового репозитория.

GitHub Actions, GitHub Pages и автоматическая доставка изменений на Sites в этом переносе не настраиваются. Коммит в `main` сохраняет исходники, но сам по себе не меняет опубликованную игру. Для обновления прежнего сайта нужен доступ к существующему Sites-проекту и его workflow публикации, описанный выше.

Ссылку для друзей меняют только после успешной публикации и проверки новой площадки. Текущая публичная beta продолжает работать независимо от распакованного архива.
